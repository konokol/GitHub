# 文档与进度维护规约

## 1. 核心进度文件 (`docs/progress.md`)
- **定位**: 项目全景视图，仅记录高层级进度。
- **内容要求**:
  - **聚焦任务**: 关注每个项目/Feature 下的关键任务完成情况（使用任务列表格式）。
  - **状态清晰**: 每个模块必须有明确的状态（如：✅ 已完成、🚧 进行中、⏳ 待开始）。
  - **严禁过于细节**: 这里的进度表**不要**列出具体的文件清单。
- **关联引用**: 通过链接指向各 Feature 文件夹下的详细计划或进度文档。

## 2. Feature 级进度 (`docs/<feature>/...`)
- **定位**: 局部细节视图。
- **内容要求**:
  - 记录具体的任务细节、Bug 修复点、文件清单及其状态。
  - 作为 Feature 内部的 Single Source of Truth。

## 3. 任务完成与 Review 报告 (HARD RULE)
- **要求**: 每个任务完成之后，**必须**产出一份详细的 **Review 报告**（存储在 `docs/<feature>/review_reports/` 下）。
- **报告内容**:
  - **变更概述**: 简述修改了哪些功能。
  - **技术细节**: 关键代码实现和架构调整。
  - **自测情况**: 单元测试和集成测试的通过情况。
  - **遗留问题**: 尚未解决的边缘情况或后续优化点。
- **流程**: AI 助手完成任务并自测后，提交代码并产出报告，随后由另一个模型进行 Review。

## 4. 修改规则
- AI 助手在执行任务后，必须先在 Feature 文档中记录细节。
- 随后将 Feature 文档中的关键里程碑同步更新到总进度表 `docs/progress.md` 中。
- 保持总表的简洁性，方便人类开发者快速阅读。
