# 文档与进度维护规约

## 1. 核心进度文件 (`docs/progress.md`)
- **定位**: 项目全景视图，仅记录高层级进度。
- **内容要求**:
  - **聚焦任务**: 关注每个项目/Feature 下的关键任务完成情况（使用任务列表格式）。
  - **状态清晰**: 每个模块必须有明确的状态。
  - **严禁过于细节**: 这里的进度表不要列出具体的文件清单。

## 2. Feature 级进度 (`docs/<feature>/...`)
- **定位**: 局部细节视图，记录具体的子任务、Bug 修复点和文件清单。

## 3. 任务交付与 Review 流程 (HARD RULE)
本项目采用 **“双模型协作”** 模式：
- **执行模型 (Current Agent)**:
  - 负责代码编写、重构与自测。
  - 任务完成后，产出一份 **“任务完成简报”** (Summary)，记录：
    1. 主要改动逻辑。
    2. 自测通过情况。
    3. 待 Review 模型关注的重点。
- **Review 模型 (Another Model)**:
  - **由 Review 模型负责** 生成最终的 **“Review 报告”**。
  - 报告应存储在 `docs/<feature>/review_reports/` 目录下。
  - 审核执行模型的代码质量、规约遵循情况及逻辑正确性。

## 4. 修改规则
- 执行模型在执行任务后，必须同步更新 `docs/progress.md` 状态。
- 所有新增文件必须在对应的 Feature 文档中登记。
